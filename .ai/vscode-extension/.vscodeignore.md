# .vscodeignore

> Last updated: 2026-06-20 | Protection: STANDARD

## Purpose

Controls which files are excluded from the packaged SpinShare VS Code extension.

## What It Does

- Excludes source files, tests, local workspace dependencies, and build
  artifacts that should not ship.
- Allows required extension runtime artifacts to remain in the VSIX.

## Public API

| Name | Type | Description |
|------|------|-------------|
| `.vscodeignore` patterns | Packaging config | Consumed by VS Code extension packaging. |

## Dependencies

- External: VS Code extension packaging tooling.

## Important Notes / NEVER Change

- Do not include root workspace `node_modules`.
- Do not exclude extension runtime files required after install.
- Negated include patterns must come after broad excludes.

## Planned Change (2026-06-15)

Keep excluding normal `node_modules`, but allow the bundled
`cli-wrapper/node_modules` PTY runtime required by the installed wrapper.

## Implemented Change (2026-06-15)

Added `!cli-wrapper/node_modules/**` after the broad `node_modules/**` ignore.

## Verification (2026-06-15)

- VSIX package listing showed
  `extension/cli-wrapper/node_modules/@homebridge/node-pty-prebuilt-multiarch/`.
- Direct VSIX zip inspection found 332 PTY package entries, including

## Bug Fix Plan (2026-06-20 Marketplace package cleanup)

**Bug:** The broad `!cli-wrapper/node_modules/**` force-include causes `vsce`
to package the complete PTY dependency tree. The resulting VSIX contains about
28 MB of uncompressed `.pdb` debug symbols plus native build sources and
scripts that are not used at runtime. Later ignore patterns cannot override
this negation because `vsce` treats any matching negated pattern as an explicit
include.

**Fix Strategy:** Replace the broad negation with narrow allow-list patterns
for the PTY package manifest, JavaScript runtime, native `.node` binaries,
required `.dll` / `.exe` helpers, and the Unix `spawn-helper`. Add an explicit
`cli-wrapper/node_modules/**` base exclusion first: the root `node_modules/**`
pattern does not exclude this nested tree, so negations alone do not form an
allow-list. Keep source maps, debug symbols, tests, source trees, and build
scripts excluded.

**Regression Risks:** Omitting a native helper would break PTY startup on the
packaging platform. Verify the final archive contents and run a packaged-runtime
smoke test that loads the PTY module and starts a trivial command.

**Test Plan:** Package a fresh production VSIX, assert that required runtime
artifacts remain, assert that `.pdb` and native source files are absent, and
compare compressed package size with the previous artifact.

**First Verification Attempt:** The read-only validator rejected
`binding.gyp`, proving the nested tree was still being included. Root cause was
the missing explicit `cli-wrapper/node_modules/**` exclusion; add it before the
narrow negations and rerun.

## Implemented Change (2026-06-20 Marketplace package cleanup)

Added the explicit nested dependency exclusion and narrow runtime negations.
The VSIX now retains the PTY package manifest, license, JavaScript runtime,
native `.node` binaries, and required Windows helpers while excluding `.pdb`
files and native build/source trees.

## Verification (2026-06-20)

- Full prod/local rebuild produced 101-entry packages at 3.79 MB each, down
  from the previous 10.9 MB / 349-file artifacts.
- Read-only validation found no prohibited `.pdb`, source, or build payloads.
- Both artifacts retain the PTY runtime and native `.node` files.
- The bundled PTY spawned `cmd.exe`, emitted `spinshare-pty-ok`, and exited 0.
